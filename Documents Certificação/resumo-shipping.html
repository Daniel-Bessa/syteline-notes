Using Shipping
Resumo de estudo — Workbook de certificação
Resumo
🗺️ Quote to Cash — visão geral do processo ▶
•O Infor Industry Process Catalog (IPC) é conteúdo pré-configurado para o CloudSuite Industrial (SyteLine), com processos, configurações e casos de teste alinhados com as necessidades do setor do cliente. Neste curso, o IPC é referido como "business processes".
•O processo Quote to Cash gere todo o ciclo de vendas: da submissão de orçamentos ao cliente até ao recebimento do pagamento.
•Quote to Sales Order — gestão de oportunidades de venda, orçamentos e conversão em encomenda.
•Sales Order to Shipping — receção da PO do cliente, criação da encomenda, acknowledgement, picking, empacotamento e expedição ao cliente. É o foco principal deste workbook.
•Shipping to Invoice — identificação dos clientes a faturar, verificação cruzada das expedições, impressão e envio da fatura.
•Invoicing to Cash — receção de pagamentos, aplicação a faturas em aberto e reconhecimento de receita.
•Return to Credit (RMA) — gestão de devoluções de cliente, emissão de créditos ou substituição de produto.
📦 Order Shipping — expedir uma encomenda ▶
•Expedir uma encomenda envolve 4 passos: gerar a pick list (localizar/recolher em inventário) → criar a packing slip (ship ou pre-ship) → embalar os artigos → processar a transação de shipping.
•Generate Order Pick List produz um relatório com todos os artigos disponíveis a expedir de uma encomenda com status Ordered.
•O form Order Shipping regista transações de shipping e acompanha os artigos expedidos por data. Antes de gerar uma fatura normal para um item/encomenda, é obrigatório expedi-lo primeiro.
•O Order Shipping tem 3 secções: (1) filtro no topo — encomenda, cliente, envios parciais/antecipados, status; (2) secção intermédia — linhas, localizações de stock, lotes, quantidade disponível a expedir; (3) secção inferior — detalhe (referência, delivery order, números de série).
•Encargos de frete: Actions > Edit Freight Charges no Order Shipping, ou no separador Amounts das Customer Orders.
•A Packing Slip pode ser impressa para shipping ou pre-shipping (nunca ambas para a mesma encomenda); imprime apenas linhas já expedidas por uma transação de shipping, mostrando a diferença entre quantidade expedida e empacotada como Qty To Pack.
⚠️ Se o Credit Hold estiver ativo (nas Customer Orders ou nos Customers), o sistema não permite expedir a encomenda desse cliente.
•Aprovações de shipping: se forem exigidas, as contas "In Process" têm de estar configuradas em: Account Receivable Parameters, Distribution Accounts, End User Type, Item Stockroom Locations, Tax Codes. A aprovação é feita no form Order Shipments (campo Qty to Approve; botão Approval Log). O relatório Shipped Not Approved lista encomendas com aprovação pendente.
💡 Se não conseguir expedir uma encomenda, verifique se o status é Ordered (não é possível expedir uma encomenda em status Planned). Corrige-se manualmente em Customer Order Lines.
•Lançamentos contabilísticos típicos: shipment manual/automático → Debit COGS / Credit Inventory; shipment com aprovação → passa primeiro por "In Process" (COGS in Process / Inventory in Process) e só depois para as contas finais; devolução antes de faturar → Credit COGS / Debit Inventory (CR Return = No); devolução após faturar → idem mas com CR Return = Yes (localização CREDIT RETURN); Return Adjustment → localização RETURN ADJ.
•Forms para verificar o que aconteceu numa transação de shipping: Customer Order Lines – Detail (Status = Filled), Customer Order Lines – Shipping (Quantity Shipped), Items (Quantity On Hand), Customer Order Listing, Journal Entries – CO Dist (referência INV CSH), Material Transactions (filtrar por Transaction Type = Ship).
🧾 Pick — recolha em inventário ▶
•O uso da funcionalidade de pack é opcional — pode-se fazer pick e ir diretamente para ship.
•Pick Workbench — cria pick lists a partir de encomendas com status Ordered; é aqui que se atribui o picker. Tem 2 separadores: Orders (seleção de linhas/releases) e Inventory (define de que localizações vem o inventário — opcional).
•Campo Group: agrupa linhas do mesmo Customer/Ship To/Ship Via/Payment Method numa única pick list quando se clica Generate.
•Campo Assign Locations: se selecionado, identifica as localizações de stock na pick list; se não, a localização terá de ser introduzida no Pick Confirmation.
•Assign Serial Numbers, Print Pick Lists, Generate Bulk Pick List (imprime lista-resumo por item/lote), Skip Order Line When Cycle Count In Process e Skip Order Line when Quantity Available is 0 são opções relevantes no Pick Workbench.
⚠️ Se houver 2 linhas do mesmo item, a validação de Qty Ready vs Qty To Pick só funciona linha a linha — a soma não é validada, pelo que ambas as linhas podem parecer "prontas" sem haver stock suficiente para as duas.
•Pick Maintenance — mostra o detalhe da pick list (Order/Line/Release/Item/Qty to Pick/Qty Picked/Status). É um passo opcional. Status possíveis: Open → Picked → Packed → Shipped (por defeito, Open).
•Pick Confirmation — regista os resultados do picking (localização, lote, número de série); botão Complete confirma a pick list. A checkbox Record Differences pré-popula a grelha com o detalhe resumido por Item/Location/Lot/S/N.
•Unpick Inventory — devolve artigos já recolhidos ao inventário (só antes de empacotar). Se inventário for "unpicked", a linha tem de ser apagada do Pick Maintenance e a pick list marcada manualmente como "Picked" para avançar.
•Pick List Splitting — divide o conteúdo de uma pick list em duas, quando o shipment tem de ser dividido (todo o conteúdo de uma pick list tem de ir para um único shipment).
•Print Pick Lists — reimprime pick lists geradas no Pick Workbench (Pick List Report, com/sem barcode, Bulk Pick List Report). Os barcodes têm de estar ativados nos Inventory Parameters.
📮 Pack — empacotamento ▶
•Pack é opcional: dá para ir de pick diretamente para ship sem passar por packing.
•Pack Workbench — agrupa pick lists num shipment. Não é obrigatório se o shipment tiver origem numa única pick list. Também permite gerar shipments diretamente a partir de linhas de encomenda ainda não recolhidas ("unpicked items"), desde que partilhem Customer/Ship To/Warehouse.
•Shipments de itens "unpicked" e shipments já com pick podem depois ser combinados via Shipment Merging — a partir daí já não podem ser expedidos separadamente.
•Package Types — define tipos de embalagem (peso, comprimento, altura, largura, packaging weight, U/M).
•Pack Confirmation — regista como os artigos serão empacotados e move o inventário da localização de packing para a de shipping/staging. A criação de packages não é obrigatória — o inventário pode ficar na localização de packing.
•No Pack Confirmation: campo Shipment (obrigatório, a menos que se selecione um Pick List), # of Packages e Total Weight calculados automaticamente, botão Create/Add to Package (cria packages numeradas sequencialmente a partir de "1"), botão Packing Slip (acede ao Shipment Packing Slip Report).
•Shipment Packing Slip Report — imprime a guia de embalagem do shipment; também acessível a partir do Pack Confirmation.
•Unpack Inventory — remove inventário já atribuído a um shipment. Opções: Return to Pick List (devolve à pick list para novo shipment) e Reduce Quantity Only (reduz a quantidade sem mover inventário para outra localização — útil quando outra transação já moveu o stock).
🚚 Ship — gestão do shipment ▶
•A funcionalidade de ship permite criar, atualizar e manter um shipment, dividir um shipment em dois, combinar vários shipments, e apagar shipments (só depois de expedidos e faturados, com todas as referências relacionadas também eliminadas).
•Shipment Master — form central para criar/atualizar/manter um shipment. Separadores: General, Charges, Pick Lists, Packages, Consignee, Consignor, Invoicee, Other.
•Separador General — Status do shipment: Open → Ready to Ship → Shipped (ou Canceled). O ID do shipment é atribuído automaticamente (highest ID + 1).
•Separador Charges — encargos de frete e diversos que atualizam automaticamente a customer order (mostra também acumulados).
•Separador Pick Lists (read-only) — mostra quantidades/lotes cumpridos por linha e localização atual; após expedir, atualiza Qty Shipped.
•Separador Consignee — morada de destino (relevante para drop-ship); Consignor — dados da empresa expedidora (de General Parameters); Invoicee — morada de faturação.
•Ship Confirmation — expede efetivamente o shipment. Só aparecem shipments com status Ready to Ship (é o único status visível neste form).
•Shipment Splitting — divide um shipment em dois (por packages, se existirem, ou por linhas/releases se não houver packages).
•Shipment Merging — combina dois ou mais shipments num só (os selecionados na grelha juntam-se ao shipment definido no cabeçalho).
•Unship Shipment — reverte um shipment (linhas), devolvendo inventário ao packing ou a stock; muda o status de Shipped para Open. Útil para cancelar ou corrigir um shipment com inventário danificado.
⚠️ Depois de fazer Unship, ainda é preciso: Unpack Inventory → Unpick Inventory → apagar a pick list no Pick Maintenance (por essa ordem). Se o shipment já foi faturado, não há linhas na grelha do Unship — nesse caso usar o Order Shipping form ou fazer um Return Material Authorization.
⚙️ Parametrização — Inventory Parameters ▶
•O form Inventory Parameters define a localização de packing e de shipping por defeito, controla a impressão de barcodes nas pick lists e configura a reserva de inventário. Tem 2 separadores relevantes: General e Labels.
•Packing Location — localização por defeito no Pick Workbench (para onde os artigos são movidos após serem recolhidos). Shipping Location — localização por defeito no Pack Workbench (para onde os artigos vão após serem empacotados).
•Inventory Reservation Process Step — define quando o sistema considera o inventário reservado: Pick Confirmation (na recolha), Pack Confirmation (no empacotamento), ou None (nunca).
•Print Barcodes on Pick Lists — ativa impressão de barcodes nas pick lists. Shipment Weight U/M — unidade usada no cálculo do peso do shipment.
•Separador Labels — Template Logical Folder (caminho dos ficheiros de template BarTender .btw) e Output Logical Folder (diretório de saída lido pelo utilitário Commander).
•Nos forms Items e Non-Inventory Items, a checkbox Allow on Pick Workbench permite/impede que o item seja incluído no processo de Pick Workbench.
📑 Delivery Orders (DOs) ▶
•Delivery orders suportam: Bill of Lading, Packing List, Pro Forma Invoice, Advance Ship Notice e geração de ASN EDI para clientes EDI.
•Composto por 3 forms principais: Delivery Orders (cabeçalho — cria/edita/apaga o DO, associado a um ship-to do cliente), Delivery Order Lines (cada linha = uma unidade de entrega, ex. camião ou contentor — conceito semelhante a uma linha de blanket order), Delivery Order Line Sequences (ligação direta a um registo de shipment de uma CO — só criado/atualizado/apagado durante ou após o processo de shipping).
•Uma linha de CO só pode ser adicionada como sequence depois de ter sido expedida — a sequence é criada automaticamente ao concluir o shipment (Shipping Processing Orders ou Order Shipping).
•Opções de faturação de DOs: por DO específico, por PO de cliente ligada a um DO (todos os shipments dessa PO faturam juntos), ou consolidando vários DOs numa única fatura (não há faturação parcial de um DO).
•Separadores relevantes no Delivery Orders: Cost Info (custos estimados/pré-pagos), Consignee (empresa que recebe o frete — herda do cliente), Consignor (armazém de origem), Invoicee (bill-to — herda do cliente), Special (instruções especiais impressas no bill of lading, checkbox Physically Shipped?), Consignor Contact.
•Delivery Order Lines — campos Rate Code (classificação de tarifa do BOL), NMFC (National Motor Freight Code) e Line Weight (peso cumulativo de todas as sequences da linha).
⚠️ A funcionalidade de Delivery Orders é diferente da de picking/packing/shipping — a Infor recomenda escolher uma ou outra, não misturar as duas abordagens.
🔗 Integrações e utilitários ▶
•Change Consolidated Invoicing Utility — muda em massa o valor de Consolidated Invoicing em registos de cliente (Process Customers) e/ou de encomenda/linha (Process Orders), definindo um intervalo de Customers e Orders.
•Integração UPS / FedEx — quando integrado, o sistema troca informação com as bases de dados da UPS®/FedEx®: escreve para uma tabela (via export map configurado no software da transportadora) valores como ShipmentID, PackageID, TrackingNumber, Weight, Void Indicator, Freight Cost.
•O CarrierCost é calculado a partir da tabela CarrierShip: se Bill To Transportation do cliente for "Shipper", aplica-se custo negativo se for um shipment anulado (void); caso contrário, aplica-se markup percentual sobre o frete cobrado ao cliente, na moeda do cliente.
•Consultar o UPS FedEx Integration Guide (Infor Xtreme) para detalhes de configuração.
•Os números de tracking ficam disponíveis com hyperlink direto para o site da transportadora em vários forms/separadores: Customer Order Lines (separador Shipping), Order Shipment, Shipment Master, Packaging Detail, Shipment Tracking. O primeiro número de tracking do shipment é o número principal (master), usado para rastrear todo o shipment mesmo que a transportadora atribua números a cada pacote individual.
🎯 Pontos-chave e erros comuns a evitar ▶
•Toda a lógica de Pick, Pack e Ship é modular: apenas o Order Shipping (expedição) é obrigatório — Pick e Pack são passos opcionais que podem ser saltados.
•Não misturar o fluxo de Pick/Pack/Ship com o de Delivery Orders — são funcionalidades paralelas e independentes.
•Todo o conteúdo de uma pick list tem de ir para um único shipment — para dividir, usar primeiro o Pick List Splitting.
•Sequência correta para reverter um erro de shipment: Unship Shipment → Unpack Inventory → Unpick Inventory → apagar a pick list no Pick Maintenance.
•Uma encomenda com Credit Hold (na Customer Order ou no Customer) não pode ser expedida — é a causa mais comum de bloqueio de shipping.
•Uma encomenda em status Planned nunca pode ser expedida — tem primeiro de passar a Ordered.
•Se as reservas de inventário forem apagadas ou reduzidas por outro processo, o shipment não é atualizado automaticamente — é necessário corrigir via Unpack Inventory antes de alterar a reserva.
•Não confundir packing slip de "ship" com packing slip de "pre-ship" — só se pode imprimir um dos dois por encomenda, nunca ambos.
